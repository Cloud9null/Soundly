# Contributing

Keep changes on a development branch with small, descriptive commits and a PR to main. Run `swift test` for domain changes. Once the app target exists, run the simulator/device build and relevant app tests too. Record actual failures; never infer playback or bit identity from a successful build.

Do not add runtime network access, telemetry, accounts, third-party code/assets, secrets or a project LICENSE without owner authorization. Do not log filenames, tags, folder bookmarks or personal library contents by default. Use synthetic audio fixtures rather than copyrighted music in tests. Keep imported files and user databases out of Git.
